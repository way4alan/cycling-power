# 輪組獨立上線清單（先不要對正式環境執行）

耗材顯示那一版（PR #16，`783f334b`）已經在正式專案 `yvgjaljdxmsmtljcmemp`。這一版把輪組從單車拆開：輪組屬於人，用裝上紀錄記得哪一段時間裝在哪台車。不要重跑舊的 SQL，也不要在預覽確認前改正式資料庫、合併或發 LINE。

順序：先備份，再跑這一支 migration，確認沒有錯誤，最後才合併並更新網站。網站若先上、表還沒有，車庫會以為沒有輪組裝在車上。

## 1. 備份

Supabase → Database → Backups，確認今天有備份。

- 要執行的：`supabase/migrations/20261118120000_member_wheelsets.sql`
- 這支不會刪車、輪組、耗材、換鍊或里程。

## 2. 本機先測

不連正式專案：

```bash
supabase/tests/run-local.sh
node --test tests/gear.test.mjs tests/challenges.test.mjs tests/pace-core.test.mjs tests/strava-verify.test.mjs
```

## 3. 正式資料庫（等確認之後）

SQL Editor 只貼 `20261118120000_member_wheelsets.sql` 再 Run。可以再執行一次。既有資料會這樣留下：

- 現在裝在未封存車上的輪組，補一筆還沒卸下的裝上記錄，開始時間用輪組建立時間。
- 已封存的車不佔用輪組，輪組本身留著。
- 完全沒有輪組的人，補一組「原廠輪組」；若還有未封存的車，裝到最早那一台。
- 里程改由基準里程加里程紀錄算出。畫面上的公里數維持現在看到的數字。
- 輪組不再綁車。之後同一時間一組輪組只裝一台車。

## 4. 然後才合併、更新網站

資料庫成功之後才合併這個 PR。Strava 的 edge function 不用先重新部署：活動寫入時，資料庫會依騎乘日期找當時裝在那台車的輪組。

## 之後怎麼算

- 單車耗材：鍊條上蠟、鍊條、煞車油、來令片、飛輪／齒盤、變把電池、把帶。
- 輪組耗材：外胎（累計公里）、補胎液。
- 換輪組從當下開始。改裝上日期會從那天起，把那台車的室外里程改算到這組輪組。
- 改一筆騎乘的車、輪組、公里或日期後，耗材公里會重算。
