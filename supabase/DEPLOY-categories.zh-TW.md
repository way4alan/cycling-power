# 團騎類型上線清單（先不要對正式環境執行）

參加、範本、路線那一版（`20261106170000_participation.sql`）已經在正式專案 `yvgjaljdxmsmtljcmemp`。這一版只加團騎類型和年度挑戰的補充欄位。不要重跑舊的 migration，也不要在預覽確認前改正式資料庫或合併網站。

順序是：備份、跑這一版 SQL、確認沒有錯誤，最後才合併並更新網站。

## 1. 備份

Supabase → Database → Backups，確認今天有備份。

準備好，先不要按 Run：

- 要執行的：`supabase/migrations/20261109150000_ride_categories.sql`
- 只想收回這一版時：`supabase/rollback_categories.sql`（既有團騎還在，類型與挑戰說明會不見）

## 2. 本機先測

不連正式專案：

```bash
supabase/tests/run-local.sh
```

確認 anon 仍被拒、團員改不了類型、管理員可以設成年度挑戰、不合法的類型會被拒絕、沒填類型的新團騎是週日固定團騎。

## 3. 正式資料庫（等確認之後）

Supabase → SQL Editor → New query。只貼 `supabase/migrations/20261109150000_ride_categories.sql`，按 Run。

成功時沒有紅色錯誤。既有團騎會變成「週日固定團騎」，報名和出席不會被刪。這份 SQL 可以再執行一次。

## 4. 然後才合併、更新網站

資料庫成功之後，才把這個 PR 合併，並把 `index.html`、`app.js`、`style.css`、`lib/pace-core.js` 放到網站。`?demo=1` 仍是示範資料，不寫正式資料庫。

只要還有尚未出發、也未取消的年度挑戰，首頁主卡就是日期最近的那一場，不論還有多久。完全沒有年度挑戰時，主卡才改成最近的週日團騎。週日團騎的報名和公告在主卡下面。每月檢定只出現在排名區的一行提示。

## 類型怎麼分

| 類型 | 值 | 首頁 |
| --- | --- | --- |
| 週日固定團騎 | `sunday` | 完全沒有尚未出發的年度挑戰時升成主卡；平常是下面那張可報名的卡 |
| 年度挑戰 | `challenge` | 尚未出發的裡面，日期最近的一場用倒數主卡，不限距離。一年至少四場，例如武嶺、阿里山 |
| 每月檢定 | `monthly` | 不做成主卡，只在排名旁顯示下次日期 |
